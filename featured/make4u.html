Summary
온라인 턴키 제조 플랫폼, 메이크포유

MAKE4U는 제조 의뢰–견적–생산–납품으로 이어지는 분절된 오프라인 과정을

하나의 플랫폼에서 통합적으로 관리할 수 있도록 설계된 온라인 턴키 제조 서비스입니다.

초기 MVP 단계에서 나타난 복잡한 정보 구조, 낮은 전환율, 사용자 혼선 문제를 해결하고 서비스 고도화와 확장에 적합한

UX·UI 기반을 마련하는 것을 목표로 UX 구조 재설계와 UI 전면 개편을 담당했으며,

전체 IA를 재정의하고 전문성과 신뢰를 전달하는 브랜드 톤을 재정의하여

사용자가 ‘빠르고 정확하게 목적에 도달할 수 있는’

단순하고 직관적인 인터페이스를 구축했습니다.

사용자가 빠르고 명확하게 목표에 도달하도록 개선했습니다.

  • 2단 구성의 GNB로 하단 콘텐츠의 View 영역 감소 및 좌/우로 분산되어는 주요 메뉴

    1단 GNB로 변경 및 주요 메뉴를 강조

    콘텐츠와 볼륨감을 위하여 회사소개, 파트너 안내 등의 신규 메뉴를 추가

  • 일러스트와 주요 타이틀이 좌/우로 배치되어, 시선과 정보가 분리되어 있음

    제조 관련 영상, 혹은 애니메이션으로 메인 이미지 교체

    핵심 문구를 재가공하여 플랫폼의 정체성을 명확하게 전달

  • 공장 노출이 메인 초반부에서 과도하게 차지함 (이탈 요인)

    공장과의 직접 컨택을 막기위해 제품 소개(포트폴리오)에 초점을 맞춰 UX 변경

    메이크포유를 통해 만든 제품이라는 이미지를 강조

    제품 사진으로 교체 및 이미지와 제품 타이틀 위주의 UX로 변경

    소재, 가공방식, 태그 등을 SEO 용도로 활용

  • 탭형식의 영상 가이드 제공시 핵심 정보를 놓칠 수 있고, 즉시 이해가 어려움

    스크롤하며 자유롭게 자신이 필요한 부분에서 멈춰서 여유있게 볼 수 있어야함

    서비스 관련 섹션을 추가, 간략한 사용법 섹션을 함께 제작

    디테일한 사용법은 노션을 활용한 이용 가이드 페이지로 이동을 유도

  • 공장 홍보(파트너 등록) 설명 부족과 사용자를 위한 내용과 혼재되어있음

    파트너 등록 시 혜택을 한 섹션에 간략히 설명 후 등록 페이지(신규제작)로 이동을 유도

    전화/메일 응대는 사람에 따라 부담이 될 수 있음. 등록 절차를 온라인 자동화

Before

핵심 기능(견적요청)이 GNB에 노출되지 않아 접근성 낮음.

검색 → 리스트 → 포트폴리오 진입 후에야 CTA가 보여 요청 흐름이 길고 단절.

의뢰 주체가 메이크포유가 아닌 ‘공장’처럼 보여 역할/브랜드 인지 혼란.

견적요청까지 총 8단계로 이탈 가능성 증가.

After

GNB에 핵심 메뉴로 배치해 바로 진입 가능.

포트폴리오 내 중복/혼동 CTA 제거로 진입 경로 단일화.

5단계 플로우를 1단계로 통합해 전환 흐름 단순화.

중복 입력 항목 통합·정리로 Form 필드 최소화.

Before
ㆍ문제
가입 과정이 6단계로 분절되어 이탈 가능성이 높고, 항목이 많아 부담이 큼.
ㆍ가설
필수 입력만 먼저 완료시키고, 상세 정보는 가입 후로 분리하면 완료율이 올라간다.
ㆍ결정
6단계 플로우를 2단계로 통합하고, 선택 정보는 온보딩/설정으로 이동.
After

Signup flow: 6 steps → 2 steps (-66%)

Form fields reduced: 20 → 9 (-55%)

가입 완료 시 가입 환영 메시지와 설정에서 상세 정보를 입력하라는 안내 모달 제공

Before

공장 정보가 과다 노출돼 직접 컨택으로 이탈 가능성이 높음.

공장 중심 홍보로 플랫폼 가치(중개/신뢰/프로세스) 가 약해 보임.

채팅/견적문의가 ‘포트폴리오=공장 문의’ 로 인지돼 흐름 혼란.

After

메뉴/구조를 포트폴리오 중심으로 재정의하고 정보 노출 기준 정리

리스트에서 제품 핵심 정보 선제공, 상세는 모달로 빠르게 전달.

‘공장’이 아닌 ‘제품’ 중심 UX로 전환해 목적/행동을 명확화.

Before
ㆍSNB
중요도 기준 없는 메뉴 배열 + 저빈도 메뉴(약관 등) 노출로 탐색 비용 증가.
ㆍ견적요청서

탭/메뉴 중복과 상태 구분 부재로 리스트 스캔 어려움.

제작 진행 이후 확인 흐름이 분리돼 전환이 끊김.

After
ㆍSNB
저빈도 메뉴 정리 후 중요도 순 재배치, 직관적 네이밍과 파트너 메뉴 분리로 혼란 최소화.
ㆍ견적요청서

메뉴·상태 구조 단순화로 빠른 확인 가능.

카드 UI+상태 라벨로 인지 강화 및 상태별 CTA로 다음 행동 유도.

Pain Points & Approach

  • Pain Point
  • Approach
  • 전문성이 느껴지지 않고 신뢰도가 낮은 UI
  • 톤&매너를 재정의하고, 3D 비주얼을 제작해 첫 화면에서 서비스 가치를 명확하게 전달
  • 중복 메뉴와 기능으로 사용자 혼란
  • 단일, 핵심 플로우 중심으로 IA를 재설계, 메뉴 통합, 주요 메뉴 네비게이션 구조 설계
  • 웹/모바일이 분리되어 유지보수 문제와 일관된 경험 제공이 어려움
  • 반응형 기반 단일 디자인 시스템으로 통합, UX 일관성 확보
  • 회원가입/견적 작성 등의 과정이 길고 복잡해 사용자 피로도와 이탈 가능성이 높음
  • 필수 정보만 남기고 1단계로 Step 축소, 선택형 입력 위주로 재구성
  • 사진·텍스트 규칙이 없어 정보 스캔 속도와 가독성이 떨어짐
  • 컴포넌트별 사진 규격과 텍스트 길이 가이드를 정의하여 페이지의 가독성과 정돈감을 향상
  • 폼 필드 대부분이 텍스트 입력이라 입력 부담이 크고 오류 가능성이 높음
  • 드롭다운/체크박스 등 구조화된 입력 패턴으로 전환해 입력 속도와 정확도를 높임
  • SEO 설정이 되어 있지 않아 검색 노출과 신규 유입에 불리함
  • H 태그, 메타 정보, Alt 텍스트 등 기본 SEO 세팅을 진행하여 노출 가능성을 확보
  • 서비스 설명이 부족하여 사용자의 다음 행동을 유도하지 못함
  • 메인 페이지에 서비스 설명 섹션을 추가하여 서비스 목표를 명확하게 전달
